# Contributing

The bundles are compiled by an LLM, so errors are possible. The law, the linter and periodic audits catch many of
them; readers catch the rest. Contributions are welcome in four forms.

## Report a factual error

If a page misstates what a source says, open an issue on
[GitHub](https://github.com/szaghi/llm-wiki/issues) with:

- the page (its URL on this site, or its path, e.g. `high-order-capturing-schemes/wiki/methods/weno.md`);
- the claim you think is wrong, quoted;
- the evidence: the source and the place in it (section, equation, figure, page) that contradicts the claim.

A report that cites the source is checked against it and fixed. A report that only asserts a different opinion is
treated like any new claim: if a published source supports it, it enters the page as a contradiction, attributed,
next to the existing claim. Recency and confidence do not overrule a cited claim.

## Propose a source

To propose a paper for a bundle, open an issue with its DOI (or a stable URL) and one sentence on what it contributes
to the bundle's domain. A bundle's bibliography already lists its **frontier**, the works its sources cite but it has
not ingested yet: a proposal from the frontier, with its citation count, is the strongest kind.

Sources are ingested only after the maintainer has reviewed them. The PDF itself is never distributed.

## Propose a change to the law

The rules in `CLAUDE.md` exist for reasons recorded in `DECISIONS.md`. To change a rule, open an issue that reopens
the decision behind it: name the decision (e.g. D7), say what fails in practice and propose the replacement. An
accepted change updates both files together, and the decision record keeps the history.

## Contribute code or documentation

The tools (`tools/`), the tests (`tests/`) and this site (`docs/`) follow ordinary pull-request practice:

```bash
make dev      # .venv with the tools and their development extras
make lint     # ruff check and format check
make test     # pytest
make check    # okf lint of every bundle + bundle registry in sync
make docs     # build the site; fails on dead links
```

All four must pass. Commits follow [Conventional Commits](https://www.conventionalcommits.org/):
`type(scope): description`, e.g. `fix(tools): resolve every link of a line in lint_okf`, or
`docs(div-free-amr): ingest <source-slug>` for an ingestion.

Do not edit generated files: `<bundle>/wiki/bibliography.md` (generated from `bibliography.bib` by
`tools/bib_to_md.py`), the regions between `<!-- bundles:start -->` and `<!-- bundles:end -->` in `README.md` and in
the skill (regenerated by `tools/bundles.py --write`), and everything the site generator writes under `docs/`.

## How changes reach the wiki

Wiki content (`<bundle>/wiki/`) is written by the compiler, not by hand. A fix to a page is made by asking Claude Code,
inside the repository, to correct it under the law; it then lints and stages the change and proposes a commit
message. **The compiler stages; the human commits**: Claude never runs `git commit`, and no commit carries AI
co-author lines. Pull requests that hand-edit wiki pages are reviewed the same way: the change is re-applied through
the compiler so that indexes, logs, the citation record and the linter stay consistent.
